# storage Specification

## Purpose
规定新增证据与预算字段如何持久化，以及历史数据在字段缺失时的读取语义，保证口径变化不会让既有 run 变得不可读或被误读。

## Requirements

### Requirement: 新增字段落盘且历史行保持可读

trial 级新增字段（终止原因、token 分解、成本、证据边界声明）MUST 随 run 持久化；缺失这些字段的历史 run MUST 仍可读取，并将其值报告为未知，MUST NOT 读取失败、MUST NOT 报告为 0 或空字符串。

#### Scenario: 读取变更前的历史 run

- **WHEN** 客户端读取一份本变更之前落盘的 run
- **THEN** 请求成功，终止原因与成本字段报告为未知，既有字段数值不变

#### Scenario: 历史 run 不参与新指标聚合

- **WHEN** 对包含历史 run 的多次运行做成本趋势汇总
- **THEN** 未知成本的 run 被排除并标注排除原因，而不是按零成本计入趋势

### Requirement: run 记录其证据采集边界

每个 run MUST 持久化本次评测的证据采集边界信息：是否开启工具入参采集、所依据的规范与映射版本、所用脱敏处理的标识。缺少该记录时 MUST NOT 允许把该 run 与记录了该信息的 run 直接比较。

#### Scenario: 复核一个历史结论

- **WHEN** 有人要判断某个历史 run 为什么缺少参数正确性指标
- **THEN** run 记录可直接回答当时未开启入参采集，无需查配置或猜版本

### Requirement: 敏感证据可按 run 彻底删除

对包含工具入参或结果内容的 run，删除操作 MUST 一并移除其持久化的证据内容，且删除后 API 与 Dashboard MUST NOT 再返回该 run 的任何证据片段。

#### Scenario: 删除后无残留

- **WHEN** 一个开启了入参采集的 run 被删除
- **THEN** 相关查询接口返回不存在，且没有任何缓存或衍生产物仍可读出这些内容

### Requirement: 每次 trial 的证据独立存档并可取回

系统 MUST 把一次 trial 采集到的证据按 trial 独立持久化，并 MUST 能在不重新运行被评系统的前提下将其完整取回以支撑重新评分。证据取回 MUST 保留每条读数的来源级别与缺失原因。

#### Scenario: 重评所需的证据齐备

- **WHEN** 对一次历史 run 的某个 trial 重新评分
- **THEN** 当时采集的全部证据（含来源级别与缺失说明）可被完整还原，评分器无需回查被评系统

#### Scenario: 证据未落盘

- **WHEN** 某 trial 的证据因写入失败而不完整
- **THEN** 该 trial 的重新评分被拒绝并说明证据不完整，而不是用残缺证据得出一个新结论

### Requirement: 判定历史与证据一并保留且可指向当前结论

持久化 MUST 同时保存每次 trial 的判定历史（每条含其评分口径标识与时间）并标明当前生效结论；读取历史 run MUST 能同时得到原结论与后续重评结论。

#### Scenario: 读取一个被重评过的 run

- **WHEN** 客户端读取一个曾重新评分的 run
- **THEN** 响应中既有当前结论也有历史判定条目，且不会把两者混成一个数字

### Requirement: 采集到的敏感内容受留存与彻底删除约束

对被显式开启采集的敏感证据（模型输入输出正文、工具入参结果），系统 MUST 支持按结果整体删除，删除后 MUST NOT 在任何查询、导出或衍生产物中残留其内容；未开启采集时 MUST NOT 落盘这些内容。

#### Scenario: 删除后无残留

- **WHEN** 一个开启了正文采集的结果被删除
- **THEN** 其证据、判定条目与派生缓存均不再可查到任何正文片段

#### Scenario: 默认不落盘

- **WHEN** 套件未开启任何内容采集
- **THEN** 存储中不存在模型输入输出正文，只存在来源标记与计数类观测
