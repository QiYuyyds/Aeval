# trace-provider Specification

## Purpose
把任意来源的 trace span 归一化为框架内部的标准观测：定义属性词汇表的映射方式、规范版本声明，以及「读不到」与「读到零」的语义区分。

## Requirements

### Requirement: span 归一化由版本钉定的翻译表驱动

系统 SHALL 通过一张声明了其所依据规范版本与自身版本的映射，把 span 归一化为标准观测字段（工具名称、工具调用成败、输入/输出/推理/缓存 token、会话标识、agent 名称与版本、调用时延）。任何特定宿主的私有属性名 MUST NOT 以框架内常量形式存在，MUST 表达为该映射中可替换、可扩展的条目。

#### Scenario: 标准埋点的 trace 开箱可读

- **WHEN** 一个只按 OTel GenAI 属性埋点的 agent 被评测
- **THEN** 其工具调用数与 token 用量为非零值，无需任何宿主专用配置

#### Scenario: 宿主私有词汇以配置接入

- **WHEN** 某宿主的 trace 使用自有属性命名
- **THEN** 通过增加映射条目即可接入，框架源码与内置评分器不需要修改

### Requirement: 字段缺失与字段值为零语义分离

归一化输出 MUST 区分「该字段缺失」与「该字段值为 0」，且缺失 MUST 附带原因（provider 未覆盖该属性 / 规范版本不认识该属性名 / trace 中确实没有这类调用）。系统 MUST NOT 以 0 代替未知。

#### Scenario: provider 未覆盖某属性

- **WHEN** trace 后端没有暴露推理 token 数
- **THEN** 该字段报为缺失并给出原因，而不是 0；依赖它的指标报证据不足而非零值

#### Scenario: 属性名不被认识

- **WHEN** span 上出现映射不认识的标准属性名
- **THEN** 运行日志与 run 记录中列出未识别属性名清单，供映射更新，且不静默丢弃

### Requirement: 后端摊平交付的属性必须还原为契约形状

当 trace 后端的读取结果不以单个属性集合、而以**摊平列**交付属性时（含把带点号的属性名按前缀收进一个以该前缀命名的嵌套结构），provider MUST 将其还原为点号键的属性集合后再交给归一化层。无法还原时 MUST 按「证据缺失」归类并给出原因，MUST NOT 交付空属性集合 —— 空属性会被下游读成「这条 trace 里确实没有工具调用」，从而把取证通道故障伪装成 agent 的真实表现。

#### Scenario: 点号键被后端按前缀嵌套

- **WHEN** 后端把宿主的点号属性名存成一个以前缀命名的嵌套结构
- **THEN** 归一化后仍能读到工具名与 token 用量，工具与轮次计数非零

#### Scenario: 整场 trace 一个属性都读不到

- **WHEN** 一次取回的全部 span 属性集合为空，而后端确实给出了属性列
- **THEN** 该情形按取证通道故障报告（附缺失原因），而不是产出一组全为 0 的过程指标

### Requirement: 归一化口径可复现

每个 run MUST 记录其归一化所依据的规范版本与映射版本，使历史 run 可被判断为同口径或不同口径；跨口径的历史数据 MUST NOT 被默认视为可直接比较。

#### Scenario: 映射条目更新后复核旧结论

- **WHEN** 维护者改动了映射条目并想确认新旧 run 的过程指标是否可比
- **THEN** 两个 run 各自记录的规范版本与映射版本可直接对照，不一致时比较结果被标注为跨口径

### Requirement: 取证通道不可用时按缺失处理而非崩溃

当 trace 后端不可达、未安装或返回空结果时，受影响字段 MUST 按缺失归类并说明原因，整场 run MUST NOT 因此失败，且该 trial 的证据状态 MUST 可被下游归类为不可信结论。

#### Scenario: 未安装可选依赖

- **WHEN** 运行环境未安装可选的 trace 后端依赖
- **THEN** run 正常完成，过程指标一律报缺失并附「provider 不可用」原因，而非报 0
