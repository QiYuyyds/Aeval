# graders Specification

## Purpose
规定评分器可以消费哪些证据、以何种边界消费：包括只依赖归一化观测、工具入参这类敏感证据的默认不采集与按套件 opt-in、开启后的脱敏边界，评分结论必须自陈所见证据的可审计要求，以及各判据（含乘性安全门）如何合成为一个总分。

## Requirements

### Requirement: 内置评分器只消费归一化观测

工具类与轨迹类的内置评分器 MUST 基于归一化标准观测判定，MUST NOT 依赖任何宿主的私有属性名，也 MUST NOT 以 span 名称子串匹配作为识别依据。

#### Scenario: 换宿主不改评分器

- **WHEN** 被评测的 agent 来自另一个使用不同埋点词汇的系统
- **THEN** 同一套评分器仍产出可比结论，差异只体现在映射配置上

### Requirement: 工具入参与结果默认不采集

工具调用的入参与结果默认 MUST NOT 被采集或持久化；仅当套件显式声明开启、且 trace 中确实存在该属性时方可使用。条件不满足时，依赖入参的判定 MUST 报「证据不可用」并说明缺的是哪一项，MUST NOT 判 agent 未通过。

#### Scenario: 未开启采集

- **WHEN** 套件未声明开启入参采集而某指标需要入参
- **THEN** 该指标结论为证据不可用，通过率的分子分母均不受影响

#### Scenario: 开启但上游未埋点

- **WHEN** 套件声明开启，但该 agent 的 trace 没有入参属性
- **THEN** 结论仍为证据不可用，原因标明为 provider 未提供，而非采集被关闭

### Requirement: 采集开启时脱敏为默认启用的必经环节

一旦开启入参/结果采集，数据 MUST 经过默认启用的脱敏处理后方可进入证据存储、API 响应与 Dashboard；未经脱敏的原始值 MUST NOT 落盘。脱敏处理 MUST 保留可判定性（例如以摘要替代原文而非删除字段），且所用处理的标识与版本 MUST 记录在 run 上。

#### Scenario: 入参含凭据样式内容

- **WHEN** 被采集的工具入参中含有密钥样式字符串
- **THEN** 呈现与落盘的是脱敏形式，且参数比对仍可基于同一脱敏函数稳定进行

#### Scenario: 替换脱敏实现

- **WHEN** 使用者提供自己的脱敏处理
- **THEN** 框架不再叠加默认处理，且 run 记录改为其标识

### Requirement: 评分结论必须自陈所见证据

每个评分结果 MUST 能说明它实际消费了哪些证据、哪些字段当时缺失，使人工复核时无需猜测结论依据。

#### Scenario: 复核一个可疑的零分

- **WHEN** 有人质疑某 trial 的工具判定
- **THEN** 结果中可见当时观测到的调用条数与缺失字段清单

### Requirement: 评分器按声明的证据级别取信

每个评分器 MUST 声明它允许消费哪些来源级别的证据，未声明的来源 MUST NOT 被其用于判定。默认级别 MUST 为「评测侧独立取证」与「接入适配层交付」，即**不含被评方自报**；收紧为只认评测侧取证 MUST 是一种可选声明，用于被评方与被评系统不属于同一信任域的场合。

#### Scenario: 状态检查默认不采信自报

- **WHEN** 一个检查环境终态的评分器面对被评方自报的文件清单
- **THEN** 它不据此判定通过；只有在存在评测侧取证或适配层交付的读数时才给出通过或失败的结论

#### Scenario: 显式降级需留下记录

- **WHEN** 套件显式声明某评分器可以采信被评方自报证据
- **THEN** 该声明生效，同时随结果落盘并在报告中可见，使这个结论可被识别为弱证据判定

### Requirement: 仅凭被评方自报证据不得判定 trial 通过

除非套件显式允许，一次 trial 的通过结论 MUST 至少有一条来自「评测侧独立取证」或「接入适配层交付」的证据支撑；只由被评方自报内容支撑的通过 MUST 判为无效并说明缺哪一级证据。

#### Scenario: 自称完成但无外部证据

- **WHEN** 被评系统声明已创建某文件，而评测侧取证与环境状态都没有该文件
- **THEN** 该 trial 不判通过；若完全没有可信证据则判无效，而不是判通过或按自报内容给分

### Requirement: 结论必须披露它依赖的最弱证据级别

每个 trial 的通过结论 MUST 标明支撑它的证据里最弱的那一级，使"由用户自己写的适配层交付"与"由评测侧独立取证"两种情形在同一份报告里可被区分 —— 前者在自评场景成立，当被评系统与适配层属于同一方时不再成立。

#### Scenario: 同一分数不同分量

- **WHEN** 两个 trial 都判通过，一个只有适配层交付证据、另一个有评测侧取证证据
- **THEN** 报告能直接看出两者证据强度不同，而不是显示为同一个 1.0

#### Scenario: 收紧后不满足即不判通过

- **WHEN** 某评分器被声明为只认评测侧取证，而本次只有适配层交付的读数
- **THEN** 该结论按无效或失败处理（按其声明的缺证语义），而不是降级采信

### Requirement: 环境状态判定必须声明所依据的时刻

检查环境状态的评分器 MUST 声明其判定所依据的时刻：结束时成立、结束时不成立、历史上任一时刻成立，或**最后一个注入事件之后成立**；默认 MUST 为「结束时」。所用时刻 MUST 随结论落盘可见。声明「事件之后」而本次运行没有任何注入事件时，MUST 报证据不足并说明缺的是事件注入，MUST NOT 退化成「结束时」判定而不加标注。

#### Scenario: 建完又删除

- **WHEN** 被评系统中途创建了目标文件、结束时已不存在
- **THEN** 按默认「结束时」判定为不成立；只有显式声明"任一时刻"的判据才会计入中途状态

#### Scenario: 探针不可用时不猜时刻

- **WHEN** 接入方未提供运行中探针，只有结束态读数
- **THEN** 判"任一时刻成立"的判据报证据不足，而不是拿结束态冒充全时段观测

#### Scenario: 事件之后才检查副作用

- **WHEN** 一个判据声明「最后一个注入事件之后成立」，运行中在第 2 轮后注入了一个外部改动事件，且事件之后有一次环境读数
- **THEN** 判定只依据该事件之后采集的读数，并在结论里标注所依据的时刻与事件序号

#### Scenario: 声明了事件时刻却没有事件

- **WHEN** 判据声明「事件之后成立」，而该 trial 的会话没有注入任何事件
- **THEN** 该判据报证据不足并指明无注入事件，而不是静默按结束态判定

### Requirement: reward_basis 乘性安全门按乘子合成总分

套件 MUST 能把判据声明为门（gate）并选择乘性合成：门各带一个乘子因子，总分 MUST 等于各门因子与基础分的乘积，使单个硬性维度的失败按乘子塌缩总分而不是被其他维度平均稀释。未声明乘性合成的套件 MUST 维持现状（加性/均值合成），门机制不得改变其分数。每个门的因子、生效结果与所依据的证据级别 MUST 随结论落盘并在报告可见。

#### Scenario: 门失败塌缩总分

- **WHEN** 一个套件声明乘性合成、基础判据得分 0.9，且一个因子为 0 的门判为失败
- **THEN** 该 trial 的合成分等于 0，无论其他维度得分多高
- **AND** 结论中可见该门的因子与失败原因

#### Scenario: 门证据不足不冒充生效

- **WHEN** 一个门声明只取信 harness 级证据，而该 trial 的 harness 读数缺失
- **THEN** 该门不生效（不乘任何因子），结论标注门未生效的原因
- **AND** 不得以 subject 级自报证据替代门判定

#### Scenario: 未声明乘性的套件分数不变

- **WHEN** 一个套件未声明乘性合成
- **THEN** 其合成分与 0.2.0 的加性/均值口径一致
- **AND** 门相关字段不出现在其结论中（或明确标为未启用）

### Requirement: 判分输入必须对同一份归档证据确定

对同一份归档证据与同一份判分配置，评分器构造的判分输入 MUST 完全由二者决定：重复评分 MUST NOT 因进程差异、集合迭代顺序或运行时随机化而产生不同的输入。判分输入不可复现时，"这次结论变了，是量具变了还是被评方变了"这一类事后审计就失去依据 —— 现有"结论自陈所见证据""披露依赖的最弱证据级别"等要求都以"重评时看到的是同一份东西"为前提。

#### Scenario: 跨进程重评同一批字节

- **WHEN** 同一份归档证据在两个相互独立的进程中各被重评一次，判分配置未变
- **THEN** 两次构造出的判分输入逐字节相同，判定结论相同

#### Scenario: 被评记录含多个同类条目时顺序稳定

- **WHEN** 一次 trial 的被评记录里出现多个同类条目（如多种工具调用），且判据把该清单呈现给判定方
- **THEN** 清单在判分输入中的次序稳定且不随进程变化，不会因次序不同而让同一份证据读成不同的表述

#### Scenario: 修复确定性属口径变更，须可归因

- **WHEN** 判分输入的确定性被修正而可能改变历史 run 的重评结论
- **THEN** 该评分器的实现版本随之提升，翻转的判定数量可由漂移审计单独量出，而不与"换了判定模型"这类其它口径变化混成同一个数字

### Requirement: 判分器可被呈现探针检视且探针不产出结论

系统 MUST 允许以"只改变不该影响结论的呈现细节"的方式就同一份归档证据重问判分器，并报告结论是否随呈现变化。每个探针算子 MUST 声明它**保持的不变量**；说不清保持什么的改动 MUST NOT 作为探针算子存在（那测出的差异无法解释）。探针的产出 MUST NOT 成为 trial 结论、MUST NOT 进入判定条目序列或改变当前生效结论、MUST NOT 进入任何分母或门禁。

#### Scenario: 锚定呈现的差异被检出而不污染结论

- **WHEN** 同一份证据在判分模板预填值不同（其余逐字节相同）的两次呈现下得到不同的通过结论
- **THEN** 报告呈现该差异并点名算子、呈现份数与抽样种子；该 trial 的正式结论与其判定条目数均不因探针而改变

#### Scenario: 带探针的评分与不带的分母相同

- **WHEN** 一次评分开启探针后完成
- **THEN** 该 trial 的判定条目数、通过率分母与关闭探针时完全一致 —— 探针只增加诊断块内容，不增加被统计的结论

#### Scenario: 无不变量声明的改动不被接受为算子

- **WHEN** 一个会改变任务语义的改动（改写被评正文、翻转判据极性）被作为探针算子提出
- **THEN** 它因无法声明保持的不变量而被拒绝成为算子，而不是被接受后测出一个无法归因到"呈现"的差异数
