## MODIFIED Requirements

### Requirement: span 归一化由版本钉定的翻译表驱动

系统 SHALL 通过一张声明了其所依据规范版本与自身版本的映射，把 span 归一化为标准观测字段（工具名称、工具调用成败、输入/输出/推理/缓存 token、会话标识、agent 名称与版本、调用时延）。映射的内置条目 MAY 覆盖多套**公共**埋点约定，但任何特定宿主的私有属性名 MUST NOT 以框架内常量形式存在，MUST 只作为运行时注入的可替换、可扩展条目。

#### Scenario: 标准埋点的 trace 开箱可读

- **WHEN** 一个只按公共约定（OTel GenAI 或所选预设）埋点的 agent 被评测
- **THEN** 其工具调用数与 token 用量为非零值，无需任何宿主专用配置

#### Scenario: 宿主私有词汇以配置接入

- **WHEN** 某宿主的 trace 使用自有属性命名
- **THEN** 通过增加映射条目即可接入，框架源码与内置评分器不需要修改

## ADDED Requirements

### Requirement: 公共约定词汇以可选预设提供

系统 MUST 提供可按名字选择的词汇预设，其中**默认预设保持为 OTel GenAI**，使既有部署的语义不变。选择其他预设时，该约定的属性名 MUST 优先于默认条目参与读取，同时保留默认条目作为兜底，以便一个正在从旧约定迁移到新约定的应用两种埋点都能读到。可选值 MUST 可被枚举出来供人与调用方发现。

#### Scenario: 选用与自带 trace 后端匹配的预设

- **WHEN** 使用者选择 OpenInference 预设且未提供任何自定义映射条目
- **THEN** 输入/输出/缓存/推理 token、模型名、会话标识与 span 角色都从 OpenInference 属性名读到非零值

#### Scenario: 默认值不变

- **WHEN** 不指定词汇预设
- **THEN** 读取行为与本变更之前完全一致，不会因为新增了预设而改变既有 run 的数字

### Requirement: 未知词汇名在装配期报错

请求一个不存在的词汇预设时，系统 MUST 在装配阶段报错并列出可选值，MUST NOT 静默退回默认预设 —— 后者会产出一整套看似正常、实则全部报「证据缺失」的观测，比直接失败更难察觉。

#### Scenario: 拼错的预设名

- **WHEN** 配置里写了 `vocabulary="open-infrence"`
- **THEN** 装配失败并列出可选值，评测不会以一堆空指标的形式「成功」跑完

### Requirement: 预设的规范修订号随 run 记录

每个预设 MUST 声明其条目所依据的规范修订标识，并随 run 落盘，使「这份数据是在哪一版约定上读的」可复核。该标识是**取名的依据版本**，MUST NOT 要求把对应规范包变成运行时依赖。

#### Scenario: 规范改名后复核历史数据

- **WHEN** 某公共约定的属性名在新修订中改变，维护者要判断历史 run 是否同口径
- **THEN** 两个 run 各自记录的规范修订号可直接对照，不需要猜当时读的是哪一版
