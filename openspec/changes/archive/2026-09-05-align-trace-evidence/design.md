## Context

动机见 `proposal.md` — Why，行为契约见 `specs/`。

现状约束：

- 宿主私有属性名 `agenthub.*` 硬编码在 5 个框架文件里，而 `examples/mock_runner.py` 造的假 span 用的正是同一套名字——**测试套件与被测代码共享一个私有词汇，结构上无法发现与标准脱钩**。本变更把打破这个自证循环列为验收条件，而不只是顺手改 mock。
- OTel 的 GenAI 语义约定已整体从主仓库迁出到独立仓库；除 `error.type` / `server.*` / `client.*` 外，GenAI 专属条目一律处于 Development 稳定性，属性名仍会变（`gen_ai.usage.prompt_tokens` → `input_tokens`、`gen_ai.system` → `gen_ai.provider.name` 已经发生过一次）。
- 规范把 `gen_ai.tool.call.arguments` / `.result` 列为 Opt-In，并注明可能含敏感信息。
- 框架核心不得引入 OTel SDK 硬依赖（可选分组只有 `api` / `cli`），也不得 `import app.*`。
- `AgentRunner` 的返回契约在本变更中**保持不变**；结构性的证据契约变更属于后续的「采集与评分分离」变更。
- 分母语义与 `invalid` 通道由 `fix-stats-and-denominators` 定义，本变更是其「证据缺失」类信号的生产者。

## Goals / Non-Goals

**Goals:**

- 在框架与宿主之间立一条**词汇无关的归一化边界**：一次翻译，处处消费。
- 把「一次 trial 为什么结束」变成可枚举、可汇总、可与能力结论分离的事实。
- 让成本成为独立的呈现轴。
- 修掉测试套件为私有词汇背书的问题。

**Non-Goals:**

- 不引入 `observed_by` 溯源标记与取证通道隔离（属「采集与评分分离」变更）。本变更只保证归一化观测**具备**承载它的形状，不实现信任分级。
- 不让 LLM 判定看到完整轨迹（属指标目录变更）。
- 不引入容器、沙箱或任何常驻服务（属覆盖面变更）。
- 不改 `ScoreStrategy` 的枚举与计分方式。
- 不新增 Jaeger / Tempo provider；本期只把既有 Phoenix provider 与 mock 接入归一化边界。

## Decisions

### D1：翻译表，而不是「直接改成只读 gen_ai.*」

内置条目对齐 OTel GenAI 当前版本，宿主私有名字降级为表中的可替换条目。

- 备选「硬切到标准属性名」：会立刻打断宿主现有埋点，且规范仍在动，等于把耦合从「私有名字」换成「某个会变的公共名字」，没有解决根因。
- 备选「继续 `if 私有A else 公共B` 的分支判断」：就是现状的病根，且每加一个宿主就长一截。
- 真正要买的东西是「加一个宿主 = 加一条表项」，不是「用哪个标准」。

### D2：归一化为框架内定义的标准观测记录，而不是把原始 span 透传给评分器

评分器与统计层只读标准观测记录（工具名、调用成败、入参槽位、四类 token、时延、会话标识、agent 名与版本）。

- 备选「透传 span，让各 grader 自己查属性」：那会把耦合从属性名换成规范版本，仍然是分布式耦合，且每个 grader 各写一遍缺失处理。
- 这条边界同时是后续溯源模型落点：将来 `observed_by` 就加在观测记录上，而不需要再改 grader 的读法。

### D3：版本钉定 + 未识别属性清单化

默认钉当前规范版本，版本可配置；映射不认识的属性名收集成清单写进 run 与日志，而不是静默丢弃。理由：Development 级别的约定下，**「我们静默地没读到东西」必须比「我们读到了零」更容易被发现**。

### D4：`absent ≠ 0` 通过 ① 的 verdict 通道表达

本变更只负责产出「缺失」信号并说明原因，不新增第四态。因此两个 change 可以并行开发，但**合并顺序必须 ① 在前**——否则「缺失」只能继续落成 0，正是本变更要消灭的行为。

### D5：入参默认关、默认脱敏、脱敏保留可判定性

默认不采集；开启后强制经默认启用的可替换脱敏处理（摘要/哈希化而非删字段），未脱敏值不落盘，处理标识与版本写进 run。

- 备选「默认开启 + 钩子」：开箱即可算参数正确性，但会默认把敏感内容持久化进 SQLite 并进 Dashboard，与「评测资产私有」的定位相悖——私有不等于不需要最小化。
- 明确代价：**未 opt-in 时参数正确性指标不可用**。这是隐私换能力的自觉选择，需在文档写明。
- 需要精确逐字比对的用户可以自行替换成恒等钩子，但该选择会被记录在 run 上——审计时看得见是谁关的。

### D6：单价表是外部配置，框架不内置默认价目

价格变动频率远高于套件修订频率，内置价目只会产出「看起来很精确的假成本」。未配置时成本报不可计算。

### D7：预算触顶与超时的归类分野（对 ① 的细化）

- `*_budget_exceeded`：**任务约束未达成**，计为未通过，但单独归类以便与「做错了」区分。预算是任务定义的一部分，超出即失败。
- `timeout`：**评测没跑完**，走 ① 的 invalid 通道，不占分母。
- `agent_error`：属 agent 缺陷还是外部依赖不可达，**必须由接入方显式声明**；未声明则归为「需人工判定」，框架不猜。

① 里「超时归 invalid」的说法以此为准收口：只有框架强制时限才是 timeout，被评方自己声明的失败不算。

### D8：`n_total_tokens` 保留为 in+out 的派生别名

避免 Dashboard 列与用户已有套件在同一次升级里双双断裂；所有新指标一律使用分解字段，别名为只读兼容层，不用于计费推导。

### D9：mock 必须双词汇，且加一条静态检查

`examples/mock_runner.py` 改为可产出标准词汇与宿主词汇两种 trace，相关用例参数化两套都过；另加一条与 `tests/test_import_isolation.py` 同类的静态扫描，断言框架源码里不再出现宿主私有属性名字面量。**没有这条，本变更会在下一轮宿主接入时悄悄回退。**

### D10：与 ① 的能力重叠如何收口

两个 change 都对 `statistics` 与 `orchestration` 声明 ADDED 要求。`openspec/specs/` 当前为空，故各自按新能力书写；归档顺序 ① 在前，② 归档时以既存文件的 Purpose 为准并人工核对合并结果，不新增并行路径。需求名已刻意错开，避免同名冲突。

## Risks / Trade-offs

- **规范属性名仍会变** → 集中一处翻译表 + 版本进 run + 未识别清单，使漂移表现为一条可读告警而不是静默的 0。
- **脱敏后无法做逐字参数比较** → 明确把参数正确性定义为「脱敏规范化后序列的一致」，并在文档写明这是隐私换能力的取舍；需要原文比对的人自担风险替换钩子，且该选择被记录。
- **宿主真实埋点覆盖度未知，切换后大量字段从「虚高的数字」变成「报缺失」，看起来像指标退化** → 先在宿主环境跑一次对照 dry-run，产出缺失字段清单再切换；这一步作为任务前置而非事后解释。
- **token 预算触顶判定依赖 provider 及时上报用量**，滞后上报会漏判 → 文档标注 token 预算为近似判定，步数预算为可靠判定；成本预算仅在单价可算时生效。
- **默认关采集会让一批新指标开箱不可用** → 接受：宁可报「证据不可用」，也不默认采集敏感内容。文档需给出「要这些指标就开这个开关」的明确映射表。

## Migration Plan

1. 归一化观测记录与默认翻译表（纯新增，无行为变更）。
2. mock 双词汇 + 参数化用例 + 私有字面量静态检查——**此时失败用例正是本变更要修的缺陷**。
3. 评分器与统计层切到归一化观测（行为分水岭）。
4. 终止原因与预算停止；归类按 D7 收口。
5. suite 新增字段、采集开关与脱敏钩子。
6. 存储字段与历史行读取语义。
7. 文档、`docs/yaml-format.md` 字段表、README 已知限制改述。

**回滚**：第 1、2、5、6 步向后兼容可独立回滚；第 3、4 步是语义变更点，回滚需同时回滚 `examples/` 期望值与 `docs/` 相应段落。无数据库迁移脚本（新增字段读时缺省为未知）。

## Open Questions

- 推理与缓存 token 的单价是否按输入价的一定比例折算，待计费口径确认；不影响观测结构与契约。
- 成本趋势是否需要按记账币种分列（当前假设单一币种），等业务侧提出再扩。
