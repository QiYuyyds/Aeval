## Context

`graders/model_based.py` 的判分输入今天是可复现的（P0），`verdict_drift` 能把翻判归因到具体口径轴（P0 并入项）。这两件事合起来是探针的前提：**探针要测的是"改变呈现会不会改变结论"，若呈现本身不可复现，测出来的差异里混着噪声；若结论翻转无法归因，探针报出的翻转也说不清是什么造成的。**

本变更只建立"能不能回答"这件事，不修任何被回答出来的问题。动机与范围边界见 `proposal.md`；要求见 `specs/graders/spec.md` 与 `specs/statistics/spec.md`。

约束：

- 宿主四把候选 judge 凭证全为 401/402（P0 的 6.2 记录同一手）。**真实幅度今天测不出来**，方案必须在零凭证下可完整验收。
- `storage/sqlite.py` 无任何迁移机制（只有 `CREATE TABLE IF NOT EXISTS`）。新增表可行，改动既有表无路可走 —— 这是"不持久化"的一个独立理由，不只是范围偏好。
- `AgreementReport`（`core/types.py:1498`）无 axis 字段，其 `measure` 是 `Literal["cohen_kappa", "krippendorff_alpha"]`，语义已锁定为跨评分者。

## Goals / Non-Goals

**Goals:**

- 让"同一 judge 对无关呈现敏不敏感"成为框架能回答的问题，并给出可复核的数。
- 用**两个**算子建立协议，使协议被证明可泛化，而不是一个特例穿上的协议外衣。
- 双向钉死机制：构造敏感的必须报出来，构造不敏感的必须不误报。

**Non-Goals:**

- 不修锚定模板、不改系统提示词、不加截断策略。修什么是第一次测量之后的决定。
- 不设门禁、不进分母。探针只出诊断。
- 不建 YAML / CLI / REST / 看板表面，不落库。
- 不做呈现算子的第三方扩展点（entry-point 组）。协议先在内核里立住，泛化性由第二个算子证明。
- 不测 pairwise 位置偏置 —— 框架内**没有成对比较判据**，该轴无宿主。要做它得先有 pairwise 判据，那是另一个变更的前置。

## Decisions

### D1 新建呈现不变性报告类型，不给 `AgreementReport` 加 axis 字段

新报告直接复用 `cohen_kappa` / `krippendorff_alpha` 的数学，但类型独立、字段独立、呈现分块。

*备选*：给 `AgreementReport` 加 `axis: inter_rater | presentation`。否决 —— 该模型的 `measure` 语义、`raters` 字段名、以及"评分者不足则不可计算"的 reason 文案全都建立在**不同评分者**之上（`agreement_report` 的 `<2 raters` 分支在呈现轴下是错的：呈现轴一个 judge 就够）。塞进去要么产生"raters=1 却算出了 κ"这种自相矛盾的实例，要么把那些不变量全部条件化。两类量分块不混排是 ④ 已经确立的纪律，类型分开是它的实现形式。

### D2 算子必须声明保持的不变量，声明不了的直接出局

判读结果（这张表是设计的核心，不是清单装饰）：

| 候选算子 | 保持的不变量 | 判定 |
|---|---|---|
| `anchor_value` | 模板示例值只是格式说明，不该进分数 | **纳入**，首个 |
| `dimension_order` | 各维度独立打分后取平均；**求和次序造成的末位浮点差异不计为呈现敏感** | **纳入**，第二个（带此限定） |
| `irrelevant_prefix` | 无关内容不该改变结论 | 不纳入：构造"无关但等长"的前缀本身就是新变量 |
| `head_trunc` / `tail_trunc` | —— 轨迹的时间序**就是**语义 | 不纳入：破坏不变量，测出来无法归因到呈现 |
| `label_polarity` | 说不清保持什么 | **拒绝成为算子** |
| `paraphrase` | 引入了改写器这个新变量 | 不纳入 |
| `candidate_order` | 无宿主（无成对比较判据） | 无处安放 |

**dimension_order 的混淆项（查证结果，推翻本条最初的判断）。** 原本以为 `avg_score = sum(scores.values()) / len(dimensions)`（`:117`）与列举次序无关。查证 `_parse_scores` 后发现它按 `for dim in dimensions` 构建 `scores` 字典（`:201`），于是 `scores.values()` 的次序**就是**配置里 `dimensions` 的次序，而浮点加法不可结合 —— 逆序求和的结果可在末位与正序不同。

这意味着 `dimension_order` 测出的任何结论差异里，**混着一个算术伪影，而不是纯 judge 敏感性**。把它归因到"judge 对维度顺序敏感"会是错的归因，正撞 D2 自己立的规矩（说不清保持什么的改动不是探针）。

边界：D4 只比**结论**是否跨过 `threshold`，所以末位浮点差只有在恰好落在阈值上时才可能翻结论 —— 混淆项被压到一种极端情形，但没有归零。

**处理（已决）**：保留该算子，把上面这条限定**写进算子的不变量声明本身**，并让它出现在报告输出里 —— 而不是只活在本文档中。理由：探针的价值在于它的结论可被下一个人正确引用，一个读者看到"`dimension_order` 未检出敏感"时，必须同时知道"末位浮点差异本就不算敏感"，否则他会把一个被限定过的否证读成普适的否证。

*另两条出路被否*：

- **砍掉只发一个算子** —— 否决。D3 的整条论证是"两个机制不同的算子才证明协议承载的不是特例"，为一个已记录、已被 D4 压到极端情形的混淆项放弃这个论证，代价大于收益。
- **先修求和的可结合性再发** —— 否决，且理由值得记下。同一份配置下今天的求和次序是**确定的**，这不是 P0 那类可复现性缺陷；是探针自己引入次序变化才撞上不可结合。为一个测试工具去改框架算术，方向是反的 —— 那等于让探针决定框架的语义，而框架在这件事上并没有待修的毛病。

### D3 两个算子而非一个

*备选*：只做 `anchor_value`，最小化。否决 —— 一个实现看不出协议是否成立，只会得到"这套抽象刚好装得下一个用例"。两个算子分别针对**格式锚**与**列举序**两类不同机制的偏置，且共用同一份协议与同一份报告结构，才证明协议在承载的不是特例。

代价：被抽中的 trial 上 judge 调用从 1 次变 4 次（基线 1 + 锚定变体 2 + 逆序变体 1）。

### D4 测结论翻转，不测分数漂移

κ 需要类别标签；而进分母的是**通过/失败**，不是分数。所以不变性的翻转定义与统计口径同源：结论跨过 `threshold` 才算翻。分数移动量作为另一维度单独呈现（它决定"要不要修"的紧迫度，但不决定"敏不敏感"的答案）。

*备选*：对分数算 α（ordinal）。否决首版 —— 那要求先定义"多大的分数差算不同等级"，是一个未测量的阈值，正撞"先测再调"。

### D5 抽样比例不给默认值，调用方必须显式提供

探针是成本乘法，而"抽多少才够"取决于判据的翻转率 —— 那正是本变更要测的量。**在没有分布之前拍一个默认 sample，就是拍脑袋定阈值。** 因此：探针默认关闭，开启时 `sample` 必填，内核不给默认。

`seed` 同理必填，且落进报告 —— 抽样本身必须可复现，否则第二次跑不出同一个数，探针就成了新的不可复现源（那将是对 P0 的讽刺性倒退）。

对齐样本数不足时，复用既有的 `MIN_ALIGNED_RATINGS_FOR_AGREEMENT` 语义报"样本过少 + 原因"，不伪造数值。

### D6 双向替身验证，且明确它证明的不是幅度

机制验收用两个构造性替身 judge：

- **构造敏感**：判据按定义对锚定值反应（例如"预填 1.0 就给高分"）。探针 MUST 报出敏感。
- **构造不敏感**：判据只读证据正文，对呈现完全无感。探针 MUST NOT 误报。

前者证明探针能发现，后者证明探针不虚报。**两者合起来只证明机制有效，不证明真实 judge 敏感或不敏感** —— 那句话必须写在报告和文档里，不能只写在设计里，因为最容易被误读成正好在这里。

真实幅度等一把可用的 judge 凭证，届时重跑同一入口即可，不需要新的设计决定。

### D7 不建表面、不落库的判据

沿用 ④ 对 `regrade` 的处理与其理由：CLI / HTTP 表面背同大版本兼容承诺，值得单独一个变更。此处再加一条：**探针的配置形状正是这次测量要 inform 的东西** —— 在量过一次之前把它写进 YAML，等于承诺一个没验证过的形状。不持久化同理：跨 run 趋势要等一串真测量才有意义，而那串测量的前置今天不成立，且 `storage` 无迁移机制会让"先建表再说"变成不可逆的决定。

## Risks / Trade-offs

- **[真实锚定敏感度测出来是 0] →** 不是白做：它把"这个锚无害"从猜测变成有记录的结论，且协议与替身测试永久留在套件里。风险是**被误读成"探针没用"** —— 缓解是在报告里把"未检出"与"不可计算（无凭证）"严格分开，二者呈现措辞不同。
- **[替身 judge 构造敏感性可能测出一个真 judge 身上不存在的效应量] →** 记录里 MUST 标注数字来源是构造性替身，且不给它任何"真实翻转率"的称呼。P0 的 6.2 已经这么处理过（"不是真实 LLM 的翻转率……测不出来，不是没测"），沿用同一句话的形状。
- **[4 倍调用在真实凭证下会真花钱] →** 报价在调用点显式给出（份数 × 抽中 trial 数），不藏进配置。这与 P0 记录里"超最初估算的部分即真实形状"的教训一致：先报价，再跑，再记实耗。
- **[探针自身的呈现构造引入新的非确定源] →** 变体构造 MUST 逐字节可复现，且必须纳入 P0 那条跨进程一致性测试的覆盖面 —— 否则探针自己成了它要测的那个毛病。
- **[二元结论的 κ 在小样本下不稳] →** 不假装它稳：报对齐样本数，不足即报不可计算。区间不在首版给出（κ 的置信区间需要额外的方差口径，属未测量的理论假设）。
- **[两个算子仍不足以证明协议普适] →** 接受。它证明的是协议装得下两类**机制不同**的偏置，不是装得下所有偏置。成对比较位置偏置那一类明确出局（无宿主），这是已知边界而非疏漏。

## Migration Plan

1. 协议 + 两个算子 + 报告类型，同批落地（拆开会得到一个只支持单算子的协议，看不出形状对不对）。
2. 双向替身测试先写后实现（先红后绿），确保探针不是"总能报出点什么"的那种东西。
3. 零凭证下完成全部验收；真实幅度留一个已入库的重跑入口，凭证恢复后直接跑。
4. 回滚：无落库、无表面、无 schema 变更 —— 探针是纯附加调用路径，回滚即移除入口，既有判定链逐字节不受影响。
