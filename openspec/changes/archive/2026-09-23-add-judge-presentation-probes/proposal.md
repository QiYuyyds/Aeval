# 判分呈现不变性探针：先量一次，再决定要不要修

> 日期：2026-09-22 ｜ 对应研究文档 [04](../../../research/agent-eval-landscape/04-aeval-coverage-matrix.md) 第 8 行「Judge 偏差缓解 —— 缺失」，与 [06](../../../research/agent-eval-landscape/06-optimization-roadmap.md) 无对应条目（路线图未列此线）

## Why

④ 交付了 κ/α，能回答"两个 judge 是否一致"；P0 交付了可复现的判分输入与翻判归因轴。**但没有任何东西能回答：同一个 judge 对不该影响结论的呈现细节敏不敏感。**

κ 高不等于准。两个 judge 若共享同一个偏置，κ 会报"高度一致"而它们**一致地错**。这是文章那句"监控是绿的、评测却是红的"搬到判分器身上的镜像——而框架卖的就是可信测量，这是可信链上唯一一处"测量本身可能系统性错、框架却完全无感"的位置。

最可疑的一处已经在代码里：`graders/model_based.py:165` 给 judge 看的 JSON 示例是 `{"quality": 0.0}`，一个**框架自己写进去的显式锚**。judge 回归到展示值附近是已知现象。它便宜到同一份证据多问两三次就能判，而**今天没人知道它到底有没有影响**——P0 顺带确认了这个锚在 P0 范围内原样未动，仅此而已。

同样的未测面还有两处：`dimensions` 的列举次序（`:172`）原样进提示词，首因效应无防线；系统提示词 `"You are an evaluation expert."` 对所有 rubric 硬编码相同（`:88`）。

**这一刀的目的不是修它们，是把"有没有影响"变成框架能回答的问题。** 修哪个、要不要设门，都要等第一次测量出来再说。

## What Changes

1. **探针算子协议**：一个封闭的小算子集合，每个算子 MUST 声明它**保持什么不变**。说不清保持什么的（改写被评正文、翻转 rubric 极性）不是扰动，是另一个任务，不纳入。
2. **两个算子**（不是一个——协议被两个机制不同的用例承载，才证明它装的不是特例）：
   - `anchor_value`：同一份归档证据、同一份判据，只替换模板预填值（`0.0` / `1.0` / 不给值），其余逐字节相同。
   - `dimension_order`：配置顺序与逆序。其不变量含一条准确限定——求和次序造成的末位浮点差异不计为呈现敏感（该限定 MUST 出现在算子声明与报告输出里，不只写在设计文档中）。
3. **呈现不变性报告**：复用 `cohen_kappa` / `krippendorff_alpha` 的数学，但作为**新的报告类型**呈现，与跨评分者 κ/α 分块不混排。测量的对象是**结论（通过/失败）是否随呈现变化**，不是分数漂移多少——进分母的是结论。
4. **抽样与 seed**：探针是 judge 调用的乘法（N 个呈现 = N 倍调用），MUST 显式报价、按 sample 抽取、seed 落进报告使抽样本身可复现。
5. **硬规则（不可绕过）**：探针 MUST NOT 产出 verdict、MUST NOT 进入 `grade_attempts` 序列、MUST NOT 移动 `current` 指针、MUST NOT 进任何分母、MUST NOT 成为门禁。这是 P0 的直接教训——探针结果一旦混进判定序列，`verdict_drift` 会把一次扰动读成"judge 换代翻转了 N 个 trial"，伪造出审计结论。

**明确不做的表面**（两个都是范围决定，不是延期）：

- **库层入口，不暴露 YAML / CLI / REST / 看板**。沿用 ④ 对 `regrade` 的处理与其理由：这些表面背同大版本兼容承诺。探针的配置形状正是这次测量要 inform 的东西——**在量过一次之前把它写进 YAML，就是承诺一个没验证过的形状**。
- **不持久化**。单 run 即问即答。跨 run 的敏感性趋势要等一串真测量才有意义，而那串测量的前置（可用的 judge 凭证）今天不成立。

## Capabilities

### New Capabilities

（无。）

### Modified Capabilities

- `graders`：新增「判分器可被呈现探针检视，且探针不产出结论」这条要求——它给判分器加了一个新的可观察行为（探针报告），同时用一条负向要求划死它与判定链的边界。
- `statistics`：新增「呈现不变性与跨评分者信度是两类量，不得合成为同一个数」这条要求。④ 已经把"单 judge 多采样的自一致"与"评分者间信度"分开，本条补上第三类：**同一 judge 在不同呈现下的一致**。

## Impact

- **代码**：`graders/model_based.py`（模板预填值参数化 + 探针入口）；`graders/` 新增算子协议模块；`core/metrics.py`（呈现不变性报告，直接复用既有 `cohen_kappa` / `krippendorff_alpha`）；`core/types.py`（新报告类型，**不改** `AgreementReport`）。
- **不改的东西**：`storage/`（不持久化，故不新增表——顺带避开该模块**没有任何迁移机制**、只有 `CREATE TABLE IF NOT EXISTS` 的现实）；`suite.py` / YAML 校验（无表面）；`core/runner.py` 的 `CALIBER_AXES`（探针不产出 verdict，没有翻判要归因，因此**不需要**第六根轴）。
- **依赖**：无新增运行时依赖。
- **成本**：探针按定义是 judge 调用的乘法。默认 off，调用方显式开启并给 sample；报价在调用点给出，不藏。
- **验证门**：`cd packages/agent-eval && pytest tests/ -q` + `ruff check packages/agent-eval` 双范围。机制验证用**构造敏感**与**构造不敏感**两个替身 judge 双向钉（前者必须报出敏感、后者必须不误报），全程离线零凭证。
- **已知缺口（不假装闭合）**：真实 LLM 下的锚定敏感度测不出来——宿主四把候选凭证全为 401/402（P0 的 6.2 记录同一手）。机制可以今天验完，**幅度必须等凭证**。
- **后续解锁**：修锚（如果测出来确实有影响）、呈现算子的 YAML 表面、跨 run 的敏感性趋势。三者都应在第一次真测量之后才设计。
