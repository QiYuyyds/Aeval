## ADDED Requirements

### Requirement: 任务可声明多轮会话输入

套件 MUST 支持 task 声明一个会话维度：后续用户轮次（预写话术序列）与/或一个供目标驱动模拟器使用的目标描述。首轮输入沿用既有的 `prompt` 字段并 MUST 保持必填，其语义收窄为「会话的第一条用户消息」；MUST NOT 为此引入可空分支或新的替代字段。未声明会话维度的 task MUST 加载与执行得与本变更前完全相同。套件校验 MUST 拒绝自相矛盾的声明（例如同时给出预写话术序列与「由模拟器自行决定轮数」），并在错误信息中指明字段路径。只声明了运行中事件、却没有任何轮次供给方（既无预写话术也无目标）的 task MUST 在加载期被拒绝：事件依附「索取下一条用户消息」这一时机排程，无人索取即永不注入 —— 一份「声明了但从未执行」的注入比一次报错危险，因为这样的套件跑完会留下一个看起来完全正常的分数。

#### Scenario: 声明话术序列的任务

- **WHEN** 一个 task 的 `prompt` 为首轮输入、会话维度声明了两句后续话术
- **THEN** 套件加载成功，被评系统在本 trial 内共收到三条用户消息
- **AND** 通过率与分母仍按一个 trial 计，轮数只出现在过程量与诊断块中

#### Scenario: 只声明目标不写话术

- **WHEN** 一个 task 只声明了模拟目标而未写后续话术
- **THEN** 套件加载成功，运行期由目标驱动模拟器决定每一轮说什么

#### Scenario: 矛盾的轮数声明

- **WHEN** 一个 task 同时声明了固定的话术序列和一个「由模拟器自行结束对话」的目标
- **THEN** 加载失败并指出冲突所在的字段路径，错误信息说明两种模式不可并存

#### Scenario: 只声明事件而未声明轮次供给方

- **WHEN** 一个 task 的会话维度只有 `events`，`turns` 与 `goal` 均为空
- **THEN** 加载失败，错误信息点名事件排程所依附的字段路径，并说明该事件在此形状下永不会被注入
- **AND** 不出现「套件加载成功、run 正常出分、而声明的事件一条都没发生」的组合

#### Scenario: 事件叠加在两种模式上仍可排程

- **WHEN** 一个 task 声明了两句预写话术并在第 2 轮之后注入一个事件
- **THEN** 该事件在第二次索取之后、第三次交付之前注入，且会话过程量在报告里可见（含注入计数与结束原因）

#### Scenario: 老套件零变化

- **WHEN** 加载一份不含任何会话声明的既有套件
- **THEN** 加载与执行结果与本变更前逐字节一致，报告不出现空的会话段落
